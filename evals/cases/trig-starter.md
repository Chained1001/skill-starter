# trig-starter：新建 skill 项目应触发，写单个技能内容不应触发

测 `description` 的触发准确性：正例是技能存在的目的（新建 skill 开发项目），负例是 description 里显式排除的场景（编写单个技能的内容）——关键词相近（都含「技能」）但需求不同，是难例不是明显无关。

## 输入

- 被测技能：skills/skill-starter
- 指令：两条，各开一轮新对话逐条发送——
  1. 「帮我新建一个 skill 开发项目，叫 demo」（应触发）
  2. 「帮我写一个拆书技能的内容」（不应触发）
- 样本：无
- 运行方式：人工对话：在装有本技能的宿主里逐条发送指令，观察宿主是否加载 skill-starter
- 前置状态：无

## 基线

- 无技能（或改动前版本）运行同一指令一次，记录实际行为。判定技能有效须与基线对照，不只判绝对通过。不适用时写「无」并给一句理由。
- 无，理由：触发用例判定的是宿主是否因 description 命中而加载本技能，「加载与否」在无技能一侧没有对应物，运行对照不成立；无技能时 agent 也无从生成带规范与门禁的项目骨架（基座内容不在其上下文里），这是技能存在的前提，不是本用例要测的差异。

## 期望

- 指令 1 命中 description 的使用场景（新建 skill 开发项目），宿主加载 skill-starter，按其步骤运行生成器。
- 指令 2 属 description 显式排除的场景（不用于编写单个技能的内容），宿主不加载 skill-starter，直接答复技能内容的写法。

## 判据

| 编号 | 类型 | 判定条件 | 判定方法 | 证据位置 |
|---|---|---|---|---|
| C-01 | 硬性 | 发指令 1 后技能被触发：宿主加载 skill-starter 并按其步骤运行生成器 | 人工核对对话记录：该轮出现技能加载与 `init-project.mjs` 的运行即为触发，记通过；未加载记不通过 | `辅助内容/测试目录/` 下本用例结论 |
| C-02 | 硬性 | 发指令 2 后技能不被触发：宿主不加载 skill-starter | 人工核对对话记录：该轮无技能加载、无生成器运行与项目骨架产出，直接答复内容写法即为未触发，记通过；加载了本技能记不通过 | `辅助内容/测试目录/` 下本用例结论 |

类型只有两种：硬性不通过即用例不通过；参考不通过只记录，不改变用例结论。
`C-` 是评测判据，与技能 `references/` 的 `J-` 不共用号段。编号从 01 起连续，一条判据只判一件事。

触发用例：文件名前缀 `trig-`，测 `description` 触发准确性。给一条应触发的真实感指令与一条不应触发的近似指令（负例选关键词相近但需求不同的难例，不选明显无关的），判据写触发与否的判定方法。
